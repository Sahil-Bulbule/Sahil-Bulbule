## 3. Reliability: what happens if a service is down

Only two external image services remain: `github-readme-stats.vercel.app` (two cards)
and `readme-typing-svg.demolab.com` (two typing lines). Everything else is either your
own SVG file or generated by your own Action — those cannot break unless GitHub itself is down.

Every image has an `alt` attribute, so if a service does hiccup the README still reads
as intended rather than showing an empty box.

## 4. Steps to make the snake work

1. Push the files (commands in the chat reply).
2. **Settings → Actions → General → Workflow permissions** → select **Read and write permissions** → **Save**.
   This is the step that makes or breaks the snake — without it the push step fails with a 403.
3. **Actions** tab → if prompted, click **I understand my workflows, go ahead and enable them**.
4. Left sidebar → **Generate Snake** → **Run workflow** → green **Run workflow** button.
5. Wait ~40–60 seconds, then refresh your profile.

## 5. Optional: make the stats cards bulletproof

The two stats cards use the shared public instance of `github-readme-stats`, which
throttles under load. To remove that dependency entirely, deploy your own copy:

1. Fork `anuraghazra/github-readme-stats`.
2. Import the fork into Vercel (free tier is enough).
3. In `README.md`, replace `github-readme-stats.vercel.app` with your own Vercel domain in both URLs.

Nothing else changes. Do this only if you see the cards fail — many profiles never do.

## 6. Dynamic vs static

**Dynamic — live GitHub data, nothing hard-coded:**
- GitHub statistics card and most-used-languages card (GitHub API at render time)
- Contribution snake (regenerated from your real contribution grid every 12 hours)
- Profile view counter

**Static files, but animated (SVG, in your repo):**

| File | Motion |
|---|---|
| `hero.svg` | drifting glows, gradient sheen on top/bottom edges, staggered text fade-in |
| `terminal.svg` | four commands revealing in sequence, blinking cursor, ambient glow |
| `lab.svg` | six cards with staggered top-edge pulses; the "Next Step" card uses a dashed border and rotating ring to mark it as not-yet-started |
| `journey.svg` | flowing dashed track, travelling light, pulsing stage nodes; Cloud Computing and DevOps are dashed and labelled `next` |
| `skills.svg` | three counter-rotating rings around the AI core, two orbiting particles, animated dashed wires feeding seven panels, staggered panel pulses |
| `how-i-build.svg` | travelling light along the loop, pills lighting up in sequence |
| `divider.svg` | sweeping gradient with a moving light point |

**Static content:** Current Focus text, badges, skill icons, Connect section.

## 7. Note on animation technique

GitHub strips `<style>`, CSS and JavaScript from README Markdown, so none of this
relies on them. All motion is **SMIL inside SVG** — `<animate>`, `<animateTransform>`,
`<animateMotion>`, `stroke-dashoffset` and animated gradients — which GitHub serves
through its image proxy and renders normally. No JavaScript appears in any SVG.

Total weight of all seven SVGs is about 37 KB, so the profile stays fast.
